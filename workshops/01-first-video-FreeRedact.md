# 实战一：不用露面，录制第一条“截图隐私遮挡”视频

**推荐理由**：FreeRedact 已经是 Andy 的公开项目，可以直接录原创操作，不需要演员、新闻 B-roll、被授权的电影片段。要以仓库当下真实功能为准，不能录制不存在的按钮。

## A. 完成可录制的环境（10 分钟）

1. 打开项目仓库：[AIPMAndy/FreeRedact](https://github.com/AIPMAndy/FreeRedact)，检查 README 中当前的官方使用入口。不要猜部署 URL；如果在线入口不可用，就用仓库指引本地运行。
2. 新建一张**自己制作**的虚构演示截图，写上“示例用户 A / 示例邮箱 test@example.com / 示例号码 123-456-7890”；这不是客户数据。用它演示遮挡前后，而不是暴露真人资料。
3. 在 Mac 建立新的桌面空间；关闭通知，确认浏览器没有打开公司/客户数据、密钥、真实邮箱与聊天记录。
4. 打开 Mac“截屏”面板（`Shift + Command + 5`），选择录制选定部分；也可用 OBS 录屏。先录制 10 秒测试，确认 UI 字体放大后仍能看清。

**验收**：有一段 10 秒试录、一个可公开演示的虚构文件、实际能打开的 FreeRedact 环境。

## B. 先写 40 秒 Shorts

| 时间 | 原创画面 | 旁白（示例） |
| --- | --- | --- |
| 0–3 秒 | 模拟截图包含需要遮挡的信息（全部是虚构） | “分享截图前，先别把个人信息一起发出去。” |
| 3–7 秒 | FreeRedact 界面或本地环境，展示实际入口 | “我做了一个免费的开源工具，直接处理这件事。” |
| 7–23 秒 | 在真实 UI 完整执行导入、遮挡、导出（按真实界面录制） | “把自己的截图放进来，选中要遮住的区域，然后导出。” |
| 23–34 秒 | 前后结果并排，放大关键遮挡区 | “这就是前后效果。发出去之前，再检查一遍。” |
| 34–40 秒 | 开源仓库页面 | “完整免费教程在我的 GitHub，项目叫 FreeRedact。” |

**剪辑要求**：不能跳过关键步骤；若真实 UI 不具备某操作，请重写脚本，不得用合成画面冒充录屏。

## C. 6–8 分钟长视频结构

- **0:00–0:25**：展示真实的前后效果；今天解决什么问题，面向谁。
- **0:25–1:15**：如何打开工具（线上或本地，二者只选亲自验证过的一种）。
- **1:15–3:30**：第一次完整操作，从准备原始截图、遮挡区域到导出文件。
- **3:30–5:00**：第二个使用场景（微信聊天截图/合同信息），仍使用虚构内容。
- **5:00–6:20**：常见错误与排查：导出前没覆盖要遮挡的位置、文字仍可见、图片比例变化。具体功能限制以实际实测为准。
- **6:20–7:00**：谁不适合用、什么时候更合适直接裁掉敏感区域。
- **7:00–7:30**：提供 GitHub 仓库、开源教程与下一个视频。

## D. Mac 操作与输出

1. 将录屏保存为 `recording.mov`（在自己的本地 `episodes/` 目录；它已被 `.gitignore` 排除，不上传客户素材）。
2. 参考 `scripts/video_kit.py`，运行：

```bash
python3 scripts/video_kit.py --input episodes/free-redact/recording.mov --output output/free-redact-long.mp4 --mode long
python3 scripts/video_kit.py --input episodes/free-redact/recording.mov --output output/free-redact-short-draft.mp4 --mode short
```

3. **竖屏输出不是自动完成的优质 Shorts**：它会保留完整画面并补边，因此还必须在 CapCut/剪映等编辑器里手动放大关键操作区、重新做节奏和字幕。
4. 使用模板 `templates/PUBLISH_CHECKLIST.md` 检查内容、素材与封面。通过审核后由人上传 YouTube Studio；不要自动批量发布。
5. 在 `templates/RETRO_7D.md` 记录 24 小时、72 小时和 7 天的真实表现。
